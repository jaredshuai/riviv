# ADR 0001: Fail Loud —— Win32 调用失败必须显式处理

- 日期: 2026-09-03
- 状态: 已接受
- 范围: 全部 unsafe FFI 代码与错误处理路径

## 背景

riviv 是 unsafe 密集的 Win32/GDI FFI 项目。GDI 句柄创建失败、DC 状态错误、窗口类注册失败等若被静默吞掉(`let _ =` 忽略关键返回值、到处 unwrap),会伪装成「图片不显示 / 渲染异常」这类难定位的表象错误。上游 C 原版(viv.c)同类错误靠 `debug_printf` + `GetLastError` 暴露。

## 决策

两层失败语义,禁止混淆:

1. **系统级失败(不可恢复)→ fail loud**:窗口类注册、DIB/DC 创建、模块句柄等基础设施错误,带 `GetLastError` 上下文直报(当前实现:fatal MessageBox + 非零退出码)。禁止 unwrap 式随机 panic 混用,禁止静默继续运行。
2. **用户级失败(单张图片)→ 遵循原版行为**:加载/解码失败**不弹框、不退出**——保留旧图或空窗口,窗口存活。M1 无状态栏,标题保持应用名;M2 加状态栏后对齐原版文案("Failed to load image.",viv.c `LOCALIZATION_ID_STATUS_BAR_FAILED_TO_LOAD_IMAGE`)。

## 理由

内部不变量被破坏时应尽早爆炸并带上下文;边界输入(坏图片、坏路径)永远不应带崩程序——这正是上游 voidImageViewer 的行为模型(加载失败置标志+清空,窗口照常服务)。

## 权衡与后果

- 开发期更啰嗦:每个 Win32 调用都要判断属于哪一层。
- `let _ =` 仅允许用于确实无关紧要的返回值(如 `InvalidateRect` 的重绘请求),且需能说出忽略的理由。
- 与「行为对齐原版」原则的边界即在此 ADR:**内部**错误大声失败,**用户侧**输入温和降级,两者不可互相侵蚀。
